# CNC Drag Knife Workbench v0.5.0 Beta — CAM-first UX

## Base and rollback

- Fallback branch: `release/v0.4.9.8-beta-fallback`
- Feature branch: `feature/v0.5.0-beta-cam-first`
- Original v0.4.9.8 standalone file preserved on **both** branches as `app/CNC_Drag_Knife_Workbench_v0.4.9.8_Beta.html`
- New UI file: `app/CNC_Drag_Knife_Workbench_v0.5.0_Beta.html`
- `main` and `development` were not changed.
- The same-day v0.4.9.8 ZIP stored in the ChatGPT project could not be extracted through the file connector. This branch was built from the contemporaneous v0.4.9.8 standalone HTML. Verify the source against the ZIP before publishing a release.

## Goals

CAM-first workflow: **Import → Prepare → Assign Cuts → Preview → Export**.

The five stages delegate to existing Design, Cut Setup and Preview handlers instead of replacing the application state machine. The existing file-open, import, job management, selection, property-inspector and simulation controls remain in place.

A new export preflight drawer shows artwork, contour and planned-motion counts, material dimensions, safe-Z check, SVG import warning, actual toolpath-plan generation, bounds analysis, duplicate/overlap analysis, multi-pass hints and holding-tab motion. **Advisory diagnostics never supplant the existing export safety and boundary-policy decisions.** The final export action still invokes `GCode.download()`.

Keyboard stage access: `Alt+1` through `Alt+5` when focus is outside text fields; `Escape` closes the drawer. Visible focus outlines are added.

## Engine preservation

The original block from `const KnifePlanner=` through the legacy unified simulator boundary marker is byte-for-byte unchanged in the v0.5 HTML. This includes planner, compensation, bounds protection, overlap checks, G-code generation, tabs and multi-pass behavior.

Only the displayed application version, title, workflow controls, CSS and an isolated UI-only script have changed. No file-format migrations were introduced.

## Known Beta limitations

The new preflight checks are run on demand rather than constantly, to avoid unnecessary CAM rebuilds while editing. The native G-code exporter remains the authoritative validator and can still show additional boundary/overlap prompts.

No new machining modes or toolpath mathematics were added in this build.
